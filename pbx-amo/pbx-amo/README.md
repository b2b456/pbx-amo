# pbx-amo — тестовый стенд: софтфон + звонки в amoCRM

Браузерный софтфон (JsSIP) регистрируется на PBX оператора по WebSocket (WSS).
Бэкенд на Node + Neon Postgres пишет события звонков и отправляет их в amoCRM:
- номер есть в amo → звонок в историю контакта (`POST /api/v4/calls`)
- номера нет → заявка в «Неразобранное» (`POST /api/v4/leads/unsorted/sip`)
- при входящем софтфон показывает, кто звонит, со ссылкой на карточку в amo.

## Запуск

1. **Neon**: создать проект, скопировать Connection string → `DATABASE_URL`. Таблицы создаются сами при старте.
2. **amoCRM**: Настройки → Интеграции → создать частную интеграцию, дать права на контакты, сделки, неразобранное и звонки; взять токен → `AMO_TOKEN`, домен → `AMO_DOMAIN` (`name.amocrm.ru`).
3. **GitHub + Render**: залить папку в репозиторий, на Render создать Web Service (подойдёт `render.yaml`), заполнить переменные из `.env.example`.
4. Открыть `https://<сервис>.onrender.com/phone.html`, ввести `API_KEY`. Статус должен стать «на линии».

Локально: `cp .env.example .env`, заполнить, `npm install && node --env-file=.env server.js`. Тесты чистых функций: `npm test`.

## Что проверить при первом прогоне

| Что | Почему неизвестно |
|---|---|
| Оператор отдаёт WSS (`wss://…`) | Без него браузер не зарегистрируется, нужен Asterisk-шлюз на VPS |
| Звонок с неизвестного номера создаёт заявку в «Неразобранном» | Поле `service_code` и права интеграции на неразобранное проверены только по сторонним примерам |
| Звонок с известного номера появляется в ленте контакта | Формат `/api/v4/calls` сверен с документацией |
| Токен amo не протухает | Нужен долгосрочный токен; если в аккаунте его нет, потребуется OAuth с обновлением |

Статус отправки в amo виден в таблице «Последние звонки» (`amo ✓` / `amo ⚠`, причина во всплывающей подсказке) и в колонке `amo_error` таблицы `calls`.

## Ограничения этой версии

- Один SIP-аккаунт и один оператор на всё приложение (из переменных окружения). Для 5 клиентов по 15 менеджеров — отдельная таблица операторов и клиентов.
- Записи разговоров не сохраняются. Сюда добавится ссылка на запись от PBX или хранение в R2.
- Free-план Render засыпает через ~15 минут простоя: первый запрос после паузы идёт долго. Пока софтфон открыт, события работают.
- Нет рингтона и переадресации; нет click-to-call из карточки amo (нужен виджет).
- Лимит amo ~7 запросов/сек: при 75 операторах понадобится очередь.

## Софтфон в новом дизайне и виджет amoCRM

- `public/phone.html` — бело-синий софтфон: набор, история, входящий, разговор (без звука, удержание, DTMF), рингтон.
- Режим `?embed=1` — панель для iframe внутри amoCRM (кнопка «Свернуть», «В отдельное окно»).
- Ключ можно передать как `phone.html#k=API_KEY` (в адресную строку на сервер не уходит).
- Сервер разрешает встраивание только в `*.amocrm.ru`, `*.amocrm.com`, `*.kommo.com` (заголовок `frame-ancestors`).
- Папка `amo-widget/` (отдельный архив) — виджет для amoCRM: плавающая кнопка/панель, всплывает при входящем, звонок по клику на `tel:`-ссылки.
